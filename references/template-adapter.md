# 公司模板适配

先按表头含义建立字段映射，再写入；正式模板优先于本参考中的测试模板。不同布局不沿用旧行号和公式范围。

## 写入与核验

1. 读取所有工作表、标题行、明细起止行、表格对象、命名区域、数据验证、合并单元格、公式、保护和图片锚点。先保存原模板副本；不在公司原模板上清空或覆盖。
2. 记录字段映射与实际允许值。识别哪些是输入格、公式格、标签格。匹配不上的必填字段列入待补充，不把任意空格当作可填写区。
3. 票号、代码、税号、交易号写为文本；日期写日期值，显示 `yyyy-mm-dd`；金额在十进制核验后写数值，显示 `0.00`，重新汇总时按整数分或 Decimal 对照。
4. 原始字符串作为单元格文本写入，防止以 `=`、`+`、`-`、`@` 开头的销售方或事由被当作公式；真实负数金额仍用数值。保存前后回读长票号、前导零、日期和金额。
5. 达到模板容量时，先扩展明细完整行，平移相对公式，同时更新表格范围、汇总公式、下拉验证、条件格式、打印区域与页码。只复制样式、只把数据写到第 26 行均不等于扩容成功。
6. 贴图采用按稳定 ID 的映射。一票多页按页关联，可用多张预览或标明多页索引，但完整原件始终保留。图片等比例缩放并核对可读性，不能用放入一张图片替代整票检查。
7. 增加贴图槽时复制完整块：标签、值格、合并区、行高、边框、图片定位和打印设置；复制后清空旧 ID 和旧图像，验证最后一槽未遮挡前一槽。
8. 用可用重算引擎重新计算，核对独立计算的申请额与各类别总额；检查公式错误与未计算缓存。仅设置“打开时重算”不等于已经重算。
9. 每张工作表与 Word 产物回读并渲染检查，清理测试输入。记录导出/重算环境及无法验证的功能，不能让草稿显示“已审批”或“已报销”。

## 已检查的原测试模板，仅供适配参考

来源为原 Skill 引用的空白测试工作簿，2026-10-28 只读检查。此模板未随公开 Skill 打包，不能假定使用者机器上存在。用户未提供模板时采用通用草稿。

| 项目 | 实际结构 |
|---|---|
| 工作表 | 报销明细、票据贴图、填写规则 |
| 明细表头与容量 | 第 11 行为表头，第 12～36 行共 25 条，A～V 共 22 列 |
| 日期 | C 为消费日期，D 为开票日期；填写规则要求缺消费日期留空 |
| 金额 | I 票面金额，J 申请金额；G8 汇总 J12:J36，J8 统计“票据字段齐全”条数 |
| 状态 | Q 去重，R 字段核对，S 流水匹配，P6 为人工报销状态 |
| 类别下拉 | 餐饮、交通、住宿、采购、待确认；没有通讯 |
| 来源下拉 | 邮箱发票、其他发票 |
| 去重下拉 | 待查重、唯一、疑似重复、确认重复 |
| 字段下拉 | 待核对、已核对、信息不清 |
| 流水下拉 | 未提供流水、可确认匹配、疑似匹配、未匹配 |
| 贴图槽标题行 | 5、18、31、44，间距 **13 行** |
| 贴图标签 | D5/H5 等是标签；实际值格须检查布局后选择，不能覆盖标签文字 |
| 第一槽图片区 | A7:L15；其余槽为 A20:L28、A33:L41、A46:L54 |

原模板 U 列公式只做基础非空/数值和状态检查，不能独立决定可申请。它没有检查真实消费周期、申请金额是否超过票面、币种、占位词或所有公司规则；“待确认”类别和“待补充”事由可能因非空而满足条件。必须先在台账完成验证，并对有缺项的记录保持 R 为“待核对”。不能在这些条件未满足时强行写“已核对”。如用户要求修订模板公式，应另存修订副本并重新验证，不能默默改变公司正式模板。

“票据字段齐全”只说明本模板的检查项满足，不能解释为发票已查验、消费真实性已核实或审批通过。
