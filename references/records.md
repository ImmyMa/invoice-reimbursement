# 台账与本地校验器

## 数据的职责

`state/manifest.json` 是执行助手维护的持久快照，保存当前已知的来源、票据、待办及报销状态。校验脚本只读这个快照，生成批次校验报告，不负责收票或自动更新台账。

- **来源文件**保存稳定来源标识、相对归档路径、SHA-256、文件格式、原始名称、邮件与附件标识（有则记录）、下载/解析状态及失败原因。
- **票据记录**每张逻辑票据一个稳定记录标识，关联源文件和页码。历史已知记录重新发现时更新该记录的来源和字段，不分配新 ID 反复追加。不同来源同一发票的候选也可暂分记录，强标识查重后保留关联关系；不得删除其来源证据。
- **批次记录**保存输入台账版本、周期、规则依据、覆盖范围、校验报告与输出文件索引。新批次不把已有票据的报销状态重置为草稿。
- **报销状态变更**保存依据与时间。只根据明确确认或可核验审批证据，从草稿变为已提交/已报销；不要根据上一次产物是否存在推断。

多页一票关联全部页码；一份文件中有多张票建立多条逻辑记录并分别关联页码/区块。不要用整份 PDF 的哈希合并其内部不同发票。

台账附带字段可保存 `files`、`revision`、`batches` 和修订依据，校验器只使用下面的约定字段。内部状态与公司表格状态词分别映射。

## 校验器输入

Python 3.10 或以上，仅用标准库，无需网络或 API Key。从 Skill 根目录运行。输入 JSON 顶层为对象，包含 `schema_version: 1`、`invoices` 数组，可给 `allowed_categories`。

| 字段 | 类型与含义 |
|---|---|
| record_id | 非空且全表唯一的字符串；创建后稳定，不使用 Excel 行号 |
| invoice_type | `digital` 为已核验数电票，`coded` 为有代码票，其他为 `unknown` |
| invoice_number / invoice_code | 字符串，保留前导零；无代码时用空字符串 |
| seller / buyer | 票面销售方、购买方；额外保留双方税号供实际核验 |
| invoice_date / consumption_date | `YYYY-MM-DD` 或 null；不得将猜测值写为真实消费日期 |
| period_date | 用于本次周期筛选的日期或 null |
| period_basis | `consumption`、`invoice_confirmed`、`manual_confirmed`、`unknown` |
| reason | 人工归属时的明确依据；`manual_confirmed` 需要非空依据 |
| gross_amount | 价税合计的十进制字符串或 null，如 `"100.00"`；不传浮点数 |
| requested_amount | 有依据的申请金额字符串或 null，不默认把未知金额补为全额 |
| currency | 三位大写币种代码，如 CNY；汇总始终按币种分开 |
| category / project / purpose | 公司费用类别、实际项目、实际事由；占位词不能当作已核验事实 |
| field_status | `verified` 或 `pending`，表示票面与已知规则的字段核对；不代表税务查验/审批 |
| claim_status | `draft`、`submitted`、`reimbursed`、`unknown` |
| invoice_status | `normal`、`red`、`void`、`unknown` |
| source_refs | 非空字符串数组，记录原件相对路径与页码等定位信息 |
| expense_ref | 可选字符串，已核验的订单或交易证据定位；未知用空字符串，不得用自编 ID 伪装交易依据 |

`period_basis=consumption` 要求归属日期与消费日期一致；`invoice_confirmed` 要求归属日期与开票日期一致并由执行助手保留本次明确规则的证据；`manual_confirmed` 要求有归属日期和明确依据。脚本能校验字段一致性，不能证明“已确认”确实发生。

仅当票面和当前公司信息完成核对，才写 `field_status=verified`。抬头、税号、项目、事由、申请额度和真实报销资格均需执行助手核对；校验器不会自行获取这些事实。不同币种小数位规则若超过本脚本的两位精度范围，单独待确认，不在脚本中静默四舍五入。

## 运行与结果

```bash
python3 scripts/check_invoices.py state/manifest.json --start 2026-10-01 --end 2026-10-31 --out batches/2026-10/run-001/checks.json
```

将示例日期和路径换为当前任务的实际值。输入可包含完整历史快照，不能先只保留当期票再查重，否则会漏掉历史已报销记录。报告用新路径，脚本拒绝覆盖已有报告。

- 退出码 `0` 表示此次校验没有待复核/冲突，不等于所有票据都在当期或全部可报销。
- 退出码 `2` 表示已生成报告但存在待复核或冲突，查看逐条原因后继续处理无问题部分，不忽略异常。
- 退出码 `1` 表示输入、格式或文件操作错误，不把失败当作空结果或成功。
- `eligible` 仅表示此脚本有限字段条件下的草稿候选；实际公司规则、原件证据、流水占用和审批结果还需另外核对。
- 报告中每条输入恰有一个互斥去向。重复记录不再计额；强标识冲突整组隔离；历史已提交/已报销不会因重导入变为新申请。
- 已知待确认申请金额与已核验候选申请额分开，未知金额只计数量，币种不同不混加。同一输入、同一周期产生相同结论。

`review_known_requested_total` 是待复核/冲突记录的已知合法申请金额之和，可能包含尚未消解的同票候选；它不是去重后的待报销净额。`known_valid_requested_total` 是全部输入观察记录的有界金额总量，包含重复和历史记录，只用于核对状态分区，不能作为唯一发票总额或报销总额。

校验器对缺字段、非法类型、无法解析的日期/金额和缺失币种等输入格式错误返回 1 并停止本次报告。执行助手应保留错误记录及原因，修复或单列后再对有效子集校验，明确该报告的覆盖范围，不把它们静默丢弃。

校验器不会根据相似度自动删除票据、生成材料、更新台账、改变报销状态或证明票据真实。缺少可靠票号时可以先整理，但不能依靠启发式自动确认唯一；需人工核验后补充依据或维持待确认。

不同可靠票据标识但销售方、购买方、开票日期、票面金额和币种相同，也先提示疑似同一消费。若已核实是不同消费，可给每个逻辑票据不同的 `expense_ref`（例如可追溯的不同订单/交易凭据路径）；同票不同来源须使用相同证据。只有整组都有不同且完整的消费依据时才解除此项提示；缺少可靠票据身份仍需复核。校验器仅检查引用一致性，不读取或验证交易凭据。

运行随包测试：

```bash
python3 -m unittest discover -s tests -v
```

## 提交台账

先从现有版本读取快照，做增量更新；未完成的旧票仍在快照中。完成当前批次的复制、生成与一致性验证后，再提交台账版本与批次产物索引。写入临时文件、校验 JSON 完整性、确认读取后原版本未变化，再原子替换并保留上版。校验报告本身不是“已处理”或“已报销”标记。

## 标识与验证的原始依据

- [国家税务总局公告 2024 年第 11 号](https://app.www.gov.cn/govdata/gov/202411/25/522115/article.html)说明数电发票号码为 20 位，票面金额、税额与价税合计为不同要素。
- [全国增值税发票查验平台操作说明](https://inv-veri.chinatax.gov.cn/czsm.html)按票种列出不同查验项；本地强标识查重仍须核对其他票面字段，不能代替官方查验。
- [全国增值税发票查验平台查验说明](https://inv-veri.chinatax.gov.cn/fpcysm.html)说明查验结果的票面信息范围；公司报销审批另有依据。

上述口径于 2026-10-28 查阅，后续遇到未覆盖票种或规则变化时重新核对原始说明。
